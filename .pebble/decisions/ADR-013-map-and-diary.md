## ADR-013: The path map and an automatic diary
Status: accepted (2026-11-24)
Context: the Path panel shows one step at a time. The developer asked to see the roadmap as a whole and, as work goes on, what was actually done. Git history says which files changed, not what was learnt: which test went red and then green, where help was asked, which concept came up.
Decision:
- **The map** opens as an editor tab, from an icon at the top of the Path panel and from the card of a closed step. Steps are pebbles along a trail: done, in progress, to prepare. Future steps are only roadmap titles (ADR-011). Clicking a pebble shows its diary next to the map, with the step's numbers: tasks, green tests, tests seen red (ADR-010), concepts, ADRs cited.
- **The diary** is `.pebble/diario.md`, one section per step, newest first. Pebble appends to it by itself, without calling the model, from events it already sees: a step proposal accepted, a test going red or green, a balloon opened (rung and concept), "Prepare the file" accepted, a task ticked, a review with Pebble, a step closed. One line per event, short and readable.
- **The developer's notes stay.** Lines Pebble didn't write (e.g. quotes starting with `>`) are kept and never touched, like unknown lines in `percorso.md` (ADR-007).
- **"Review the step"**: from the map and from the closed-step card, it opens the Mentor with the step's diary, tasks and files, and asks for a summary of what was built, the concepts met and what is left fragile, without new code.
Alternatives ruled out: reading the diary only from git (it doesn't know about tests seen red, balloons or concepts, and needs a repository); writing the diary with the model (costs money on every event and can invent); a table instead of a map (readable but it loses the sense of a path, which is Pebble's metaphor).
Consequences: the diary grows with the project; closed steps can be collapsed in the map and in the file. It is versioned like the rest of `.pebble/` (ADR-002): the team sees how a feature was built. The events must be written once even when signals repeat (a test that stays green on every save is not a new event). The map is a webview with the same look as the Path panel.
